# mh_next_ui 编码规范

## 1. 通用原则

- 变更最小化：仅修改与需求相关文件。
- 保持一致性：遵循现有代码风格和目录结构。
- 可维护性优先：避免重复逻辑，复用公共组件/工具。
- 不提交敏感信息：token、凭据、私钥、内部账号。

## 2. TypeScript / React 规范

- 优先使用明确类型，避免滥用 `any`。
- 组件使用函数式写法和 Hooks。
- `useMemo/useCallback` 仅在必要时使用，依赖必须完整。
- 复杂逻辑优先拆函数，避免超长 JSX 渲染块。
- 命名语义化：`handleXxx` / `onXxx` / `buildXxx`。

## 3. UI 与样式规范

- 优先使用 `@mh-repo/ui` 的 `Mh*` 组件，不直接散用 antd 原生组件。
- 图标优先从 `@mh-repo/ui` 导出中获取。
- 页面样式优先 `*.module.less`，降低全局污染。
- 全局样式覆盖仅在必要场景使用（如 antd 结构覆盖）。

## 4. 菜单与路由规范

- 菜单展示数据必须与侧边栏同源，禁止双份菜单构建逻辑。
- 路由 path 和菜单 path 要保持一致。
- 平台导航逻辑集中在容器层，子组件只负责展示和回调。

## 5. 请求与状态规范

- 接口调用使用现有 SDK/服务层，不绕过既有封装。
- 异常处理要显式（日志、兜底状态或回退策略）。
- 缓存键名沿用既有约定（如 `menu-config-*`）。

## 6. 提交前检查

至少执行与改动相关的验证：

- 类型检查：`pnpm --filter <app> typecheck` 或 `pnpm check`
- 构建检查：`pnpm --filter <app> build`
- 必要时本地运行：`pnpm --filter <app> dev`

## 7. 禁止项

- 不进行无关重构或大规模格式化。
- 未确认影响前，不修改跨应用公共行为。
- 不新增任务无关依赖。
