# mh_next_ui AI 代码协作规则

## 1. 必须遵守的执行顺序

1. 先读需求和相关上下文文件；
2. 查找并复用现有实现模式；
3. 仅做任务相关改动；
4. 完成后执行必要验证；
5. 输出变更摘要与验证结果。

## 2. 强制约束

- UI 优先使用 `@mh-repo/ui` 的 `Mh*` 组件。
- 菜单改动必须保证“头部弹层与侧边栏同源”。
- 微前端改动必须检查 `entry/base/挂载容器/样式注入`。
- 不引入任务无关依赖，不做无关重构。

## 3. 文档一致性

实现前后都要遵循并维护：

- `docs/architecture.md`
- `docs/coding-standard.md`
- `docs/component-pattern.md`

若实现与文档冲突，必须在同一任务中同步更新文档。

## 4. 输出规范

- 说明改了什么、为什么改、影响了哪些文件；
- 提供执行过的验证命令与结果；
- 如有剩余风险或待办，明确列出。

## 5. 风险提醒场景

以下改动必须显式提示风险：

- 全局样式覆盖；
- 路由结构调整；
- 菜单数据流变更；
- qiankun 挂载行为变更；
- 跨应用公共包行为变化。
